# 第 61 章 从头像记录与私有桶的差异追查缺件和多件

**章节提要**　承接第 60 章「对象存储与数据库如何协作」。练习从[已有配套](https://github.com/SamChowRock/epp-public/tree/part-07/chapter-60)的副本开始。

## 61.1 为对账准备两份独立清单

沿用已经发布的头像、用户当前指针与 avatar_writes，在非空库及其配对的练习桶副本操作。记录库名、桶、键前缀、扫描起止与分别授权的只读角色。应用签名读取的身份未必有列举权，给对账者单独配置范围。两边各取多页，记录末页和错误，缺页的扫描只能交付不完整报告。

## 61.2 按当前指针和写入尝试解释差异

准备四例：当前键及字节齐全、当前键缺字节、尚在保护期的写入、无对应写入行的练习对象。先按用户与尝试 ID 连接数据库，再按对象键对照列表与精确 HEAD；将权限错误、端点故障和真正的缺件记录为不同结论。对缺当前键用原账号签发再实际 GET；私有桶的未授权读不能证明对象不存在。

## 61.3 让发布过程穿过一次扫描

在数据库取样后暂停扫描，同时发布新头像，再继续取对象清单。读者应能用扫描时间和复查时的指针说明一项可疑多件何以出现。另让一次分页请求中断，重扫该范围并合并相同键的结果。未跟踪键先保留，查备份来源、其他实例和桶的独占性，不能仅凭扫描时刻相异就删除。

## 61.4 用第二次观察决定怎样修复

缺当前键时按可信备份校验字节摘要，或通过正常发布生成新头像并复读；已跟踪且合资格的淘汰项才交给现有按 ID 清理命令。对仍无凭据的孤立对象保留证据交接。把只读盘点报告、复查动作和处置前后同一用户的读数一并交接。
