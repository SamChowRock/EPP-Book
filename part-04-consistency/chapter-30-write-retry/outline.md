# 第 30 章 创建素材与追加修订怎样承受重试

**章节提要**　承接第 29 章「幂等与审计：响应丢失后如何安全重试」。练习从[已有配套](https://github.com/SamChowRock/epp-public/tree/part-04/chapter-29)的副本开始。

## 30.1 重发同一段文本会多出什么

沿用候选采纳已有的事务和回执，在独立库用 POST /captures 创建素材，再用 POST /captures/:id/revisions 追加修订。在服务已提交、客户端尚未读到响应时截断一次连接。重发相同输入，按素材 ID 和修订号查看新增行。另让甲主动两次记下同一句话，用两个新操作键核对它们各自的素材 ID。乙使用与甲相同的键和原文，再切回甲，比较两人的实际归属与返回内容。文本相等本身不足以证明重试；本章仍在固定练习用户阶段，在隔离测试夹具中把原固定用户常量作为服务端注入值，给同库两个实例分别指定甲、乙，禁止从请求正文接收用户身份，身份篇再用独立会话复验。

## 30.2 为两种写入划定操作身份

制作一个只含编辑框、提交和继续上次提交的小页面。首次点击先把操作键、入口、已确认的账号范围与原始输入保存在该页签可跨刷新的 sessionStorage，再发请求；提交后丢响应时保留待办。刷新页面后先取服务端当前练习身份，只有与待办主人一致才可继续，原键原参提交；确认成功即清除，用户再次主动提交则新建键。退出时清除待办与编辑内容，切换身份后不得加载、展示或发出旧账号的输入。确定作用域包含当前用户及操作类别，指纹记录路径目标与经过契约解析的输入，区分空值与有效值。比较成功回放需保存的内容：创建要找回原 ID 和 Location，追加要找回当时的修订 ID 和版号，即使已经出现下一版。

## 30.3 让重复请求争用同一份决定

在现有非空库追加结构，将领用操作身份、实际写入和成功结果放在同一事务。两条连接同时提交同键同参，再试同键异参和另一用户同键。列出客户端结果、数据库新增素材数与修订数，并定位唯一约束冲突后在哪个有效事务中重读回执。故意让回执落库失败，应观察业务写入一并撤回。

## 30.4 让旧客户端继续工作

保留原先不带操作键的请求契约，说明它在断线时可查什么、缺少什么。对带键请求重放时，另起会话修改目标后再返回，辨认历史回执与当前详情。让甲提交后断网，刷新并重新取回原 ID；另做一轮甲退出再切乙，检查浏览器 Network 中没有甲的重发，乙的列表无新增。待真正的会话接入后，恢复同一页签做 Cookie 登录、退出与切换的同组断言。最后用原采纳键和既有客户端补跑，确认三个入口的结果没有相互串用。
