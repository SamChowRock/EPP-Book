# 第四篇 业务一致性：修订、候选、事务与采纳

第三篇让原文、中文意图和归属进入数据库，建立了 SQL、模型约束、连接管理与追加迁移。第四篇继续使用这些记录，研究一条业务规则涉及多个事实、多个请求或重试时，怎样让最终结果符合原先的承诺。

先明确事实再选择机制：记录保持身份，修订保存某一版输入，候选绑定具体修订；采纳将联系学习记录、正式表达与形式，事务保证需要一起提交的变化，并发控制保证竞争时的前提，幂等负责重复操作的身份。它们解决不同问题，不能相互替代。

起点为第二十四章最终代码 `part-03/chapter-24`，原文与意图上限均为2000个UTF-16单元，旧数据保留。回到C的正式源码目录并停止A/B旧产物。继续使用 PostgreSQL 18、Prisma 7.10.1、DBeaver、Postman、Inspector和自动编译重启；开发／生产入口、数据库配置分离与日志信息边界沿用前篇。仍使用固定开发用户，身份认证由第五篇接入；候选先使用少量示例输入，不调用AI或创建向量。

跟做时保留一个能从头查到尾的样本。第 25、26 章在同一份素材上保留两版原文，把候选挂在第一版。第 27～31 章让两条候选成为同一正式表达的不同学习来源，记下素材、修订、候选、表达、来源五类 ID，以及那次采纳的操作号。到了第 32～35 章，用它们查列表、翻页和读历史详情：节点应有几个，来源应有几条，修改素材后详情应显示哪版原文？先写下预测，再打开 Postman 或 DBeaver。走到第 36 章，把其中一次成功响应拿走，看看只凭保留的身份能还原哪些事实。

可以分三次停下来检查自己。学完第 26 章，画出一个旧修订和它的候选，解释“放弃”后还能查到什么。学完第 31 章，分别为“同一动作重发”和“另一个候选首次采纳”写出应相同、应不同的 ID。学完第 35 章，自己选定一个读者范围和页长，说明数据库读过的行、服务交付的项以及页面画出的节点为何可能是三个数。最后到第 36 章，用另一种业务的预约名额检验这些判断。

## 当前阶段与恢复入口

第二十五章增加 `capture_revisions`，每条旧记录得到一份迁移时已知内容，无法恢复此前已经覆盖的历史。完成后 latest 由最大 revision_no 定义；旧 captures 内容列保留初始副本，所有当前内容读取转向修订。新建使用嵌套写入，追加只写修订表，不增加 current_revision_id。序号唯一和争号409已经落实，基于过期页面的顺序提交仍可能成功；修订历史不等于完整并发编辑、幂等或审计。

第二十六章追加candidates，每版最多五个不复用的位置；旧修订初始没有候选。新建候选为pending，放弃只允许pending→discarded并保留时间，重复操作或占位冲突返回409。候选内容不改写，旧版仍可读取、补存和放弃；截至第26章，采纳表与accepted状态尚未建立。

第二十七章追加expressions、expression_forms与learning_records，并将acceptedAt及accepted状态贯通全部候选输出。采纳事务同时提交状态、表达、形式和学习关系；重复采纳或采纳后放弃返回409，历史修订仍可确认。当前每次新建表达，不做语义去重、幂等结果重放或真实登录；已有accepted数据后，第26章旧程序不能直接作为读取兼容的恢复版本。

第二十八章审核既有学习关系后增加candidate_id唯一约束，保留pending条件更新；采纳限制每次锁等待，只对P2034做最多三次完整事务尝试。双连接实验区分过期判断、条件写入、行锁、建议锁和死锁；版本支线补齐过期编辑、ABA与跨行前提。用户生命周期与现有表达锁仍是后续扩展的设计边界，当前不新增账号处置或语义复用。

第二十九章新增command_receipts，不给旧采纳回填未知操作身份。采纳Body必填operationId，按用户／操作身份协调，同一成功请求重放原201，改目标返回操作冲突；业务与响应快照共同提交，原条件更新和单候选唯一约束保留。成功回执当前不自动清理，不能把单库幂等扩展为外部副作用或完整防篡改审计。

第三十章为创建与追加增加可选Idempotency-Key，保留无键旧客户端；新回执与业务同事务，重放原ID、Location与修订版号。浏览器发送前保存待办，刷新先确认身份；固定主体夹具用于本章对照，会话阶段接入真实Cookie、预期会话和CSRF。后续章节沿用这套重试规则。

第三十一章以版本化规范化函数和用户范围内的精确内容身份复用表达；表达身份锁与唯一约束协调不同候选的竞争，每次采纳仍保留独立学习来源。迁移回填旧归属和比较值，保留旧重复表达、全部原引用与回执，仅选择一个未来复用代表。当前不做相似合并、多形式扩展或账号处置；升级后的必填列不能由旧程序继续写入。

第三十二章增加基础星图、学习列表与历史详情；两个新列表默认20、最大100，多取一行判断hasMore。公开投影约束字段和关系范围，保留旧副本可读，不新增迁移；仍是固定开发用户，尚无全量分页、语义连线或掌握程度。

第三十三章为两个列表增加显式分页与UTC半开时间区间，不改模型或迁移。旧请求不传mode时结构保持；Cursor绑定查询范围，整轮30分钟有效，读取实时数据。生产启动需持久CURSOR_HMAC_KEY，开发临时密钥随应用重建而更换；星图日期按表达创建时间，来源计数仍覆盖全部可见来源。

第三十四章保留旧素材全量默认，新增GET /captures/page；沿最新修订筛选并按素材创建时间、ID升序续页。独立浏览器对照200截断、失败不推进和集合变化，数据与迁移保持。第38章后将分页与写入回执一起接入真实请求身份。

第三十五章在学习记录上追加按用户、创建时间和 ID 排列的索引。升级前后对照同一列表、旧详情、归属条件和实际行数。页长、游标与旧数据沿用第三十三章。

第三十六章在同一个校验库用相反的采纳、放弃顺序和一次响应丢失核对终态，再用独立场次实验判断最后一个名额归谁。应用与迁移沿用第三十五章；预约表只在实验命名空间内建立。

继续使用前篇 DEV、VERIFY 与 SHADOW，数据库用途和配置入口见[第三篇导读](../part-03-postgresql/README.md#中断后从当前数据库状态接着做)。第25章关系切换及后续迁移都按有停写窗口的路径操作：停止全部旧写入口，迁移回填与核对后再启动新服务，不能把回填后启动旧程序视为安全恢复。下次继续先核对迁移记录、初始修订覆盖和当前最大序号；代码分支切换不会回滚数据库。图形请求和SQL入口随本章配套提供。自动回归沿用第二十二章的独立连接：在 `.env.test` 显式设置 `TEST_DATABASE_URL`，不读取日常开发 `.env`；第二十七章起包含临时约束和写入实验，第三十一章起清理还需保留复用的已有表达。
