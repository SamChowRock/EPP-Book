# 第四篇 业务一致性：修订、候选、事务与采纳

第三篇让原文、中文意图和归属进入数据库，建立了 SQL、模型约束、连接管理与追加迁移。第四篇继续使用这些记录，研究一条业务规则涉及多个事实、多个请求或重试时，怎样让最终结果符合原先的承诺。

先明确事实再选择机制：记录保持身份，修订保存某一版输入，候选绑定具体修订；采纳将联系学习记录、正式表达与形式，事务保证需要一起提交的变化，并发控制保证竞争时的前提，幂等负责重复操作的身份。它们解决不同问题，不能相互替代。

起点为第二十一章最终代码 `part-03/chapter-21`，原文与意图上限均为2000个UTF-16单元，旧数据保留。撤回过渡补丁并停止A/B旧产物。继续使用 PostgreSQL 18、Prisma 7.10.1、DBeaver、Postman、Inspector和自动编译重启；开发／生产入口、数据库配置分离与日志信息边界沿用前篇。仍使用固定开发用户，身份认证由第五篇接入；候选先使用少量示例输入，不调用AI或创建向量。

## 当前阶段与恢复入口

第二十二章增加 `capture_revisions`，每条旧记录得到一份迁移时已知内容，无法恢复此前已经覆盖的历史。完成后 latest 由最大 revision_no 定义；旧 captures 内容列保留初始副本，所有当前内容读取转向修订。新建使用嵌套写入，追加只写修订表，不增加 current_revision_id。序号唯一和争号409已经落实，基于过期页面的顺序提交仍可能成功；修订历史不等于完整并发编辑、幂等或审计。

第二十三章追加candidates，每版最多五个不复用的位置；旧修订初始没有候选。新建候选为pending，放弃只允许pending→discarded并保留时间，重复操作或占位冲突返回409。候选内容不改写，旧版仍可读取、补存和放弃；截至第23章，采纳表与accepted状态尚未建立。

第二十四章追加expressions、expression_forms与learning_records，并将acceptedAt及accepted状态贯通全部候选输出。采纳事务同时提交状态、表达、形式和学习关系；重复采纳或采纳后放弃返回409，历史修订仍可确认。当前每次新建表达，不做语义去重、幂等结果重放或真实登录；已有accepted数据后，第23章旧程序不能直接作为读取兼容的恢复版本。

第二十五章审核既有学习关系后增加candidate_id唯一约束，保留pending条件更新；采纳限制每次锁等待，只对P2034做最多三次完整事务尝试。双连接实验区分过期判断、条件写入、行锁、建议锁和死锁；版本支线补齐过期编辑、ABA与跨行前提。用户生命周期与现有表达锁仍是后续扩展的设计边界，当前不新增账号处置或语义复用。

第二十六章新增command_receipts，不给旧采纳回填未知操作身份。采纳Body必填operationId，按用户／操作身份协调，同一成功请求重放原201，改目标返回操作冲突；业务与响应快照共同提交，原条件更新和单候选唯一约束保留。成功回执当前不自动清理，不能把单库幂等扩展为外部副作用或完整防篡改审计。

继续使用前篇 DEV、VERIFY 与 SHADOW，数据库用途和配置入口见[第三篇导读](../part-03-postgresql/README.md#中断后从当前数据库状态接着做)。第22章关系切换及后续迁移都按有停写窗口的路径操作：停止全部旧写入口，迁移回填与核对后再启动新服务，不能把回填后启动旧程序视为安全恢复。下次继续先核对迁移记录、初始修订覆盖和当前最大序号；代码分支切换不会回滚数据库。图形请求和SQL入口随本章配套提供。
