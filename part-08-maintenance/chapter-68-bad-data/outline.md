# 第 68 章 一条历史坏记录应该让多少服务停下来

**教学规划**　接在第 66 章「调试性能与资源问题」之后。练习从[已有配套](https://github.com/SamChowRock/epp-public/tree/part-08/chapter-66)的副本开始。

## 68.1 从缺少首版修订的旧素材开始

沿现有素材模型，在非空练习库副本由维护角色构造一个只有父记录、没有任何修订的虚构样本，旁边保留一个正常素材。比较同一身份的列表、按 ID 取详情和启动就绪结果。沿列表的 LATERAL 连接及详情缺修订的分支解释差异，记录故障 ID；启动探针的实际覆盖范围以该版本配套为准。

## 68.2 按受影响的承诺划定停用范围

把样本放入两个决策场景：普通列表需要识别不完整结果，而无法判断记录归属时继续开放读取可能跨账号泄露。对每个场景明确可以提供的健康操作、应拒绝的操作和对客户端的可见信号。要求读者比较全库启动扫描成本与离线巡检，不得把漏出坏行的成功列表视为完整数据。

## 68.3 在有界扫描中记录并隔离

计划按主键分批找出无任何修订的素材，保留库名、主键、违反规则、首次及最近发现时间；扫描中止后按检查点继续。逐个练习 ID 复核后标记隔离，再以两个账号重试详情、列表和写操作，验证健康条目可用且另一账号看不到隔离原因中的私人字段。批处理中途退出后重跑应保留原事实。

## 68.4 依可信来源修复后再开放

有备份的样本按当前父记录、来源与实际历史比对，在事务中有条件补回原修订，并记录修复依据；没有证据的样本保持隔离，旧父表初始文本不能证明完整历史。复查主从属关系、两种读路径和重复执行，证据齐全后才解除隔离。
