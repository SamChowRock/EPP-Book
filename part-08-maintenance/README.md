# 第八篇　开发与维护：管理命令、构建和性能

第七篇交接一笔头像事故时，接班人拿着尝试 ID 去查引用、对象和处置结果。账号资格也常有交接，只是此前我们靠维护者在 SQL 编辑器里改一行。旧的操作回执丢了，今天重跑会不会覆盖别人刚做的恢复？这一篇从这条命令开始，把服务交给另一位开发者从头构建、执行和排障。

起点是第 52 章沿用的第 51 章配套，保留原账号、会话、记录与存储配置。第 53 章先在独立库做一次可查询的 Web 资格变更。接下来要检验换一份安装目录后 API、Worker 和 CLI 能否运行，再在实际变慢的路径上区分计算、查询和等待。这些工作针对现有的单包服务，交付环境和上线恢复进入第九篇。

| 章节 | 要处理的现场 |
| --- | --- |
| [53　为后台操作提供可靠的管理命令](chapter-53-account-cli/chapter.md) | 上午暂停后断线，下午已有恢复决定，能否重发上午的命令？ |
| [54　构建与持续集成](chapter-54-build-ci/chapter.md) | 在干净目录还原依赖，检查不同运行入口及生成文件。 |
| [55　调试性能与资源问题](chapter-55-performance/chapter.md) | 两次登录都慢且都成功，哪一次真的在数据库里等锁？ |
| [56　第八篇回顾：从维护动作到可交付产物](chapter-56-review/chapter.md) | 恢复账号以后，重发旧暂停命令却超时。找回收据，解释等待，再验证接班人手上的产物。 |
