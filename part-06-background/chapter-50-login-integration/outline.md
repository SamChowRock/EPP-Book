# 第 50 章 选读：让小程序登录与事务发件箱在同一服务工作

**选读章**　接在第 49 章「Transactional Outbox：业务和消息如何一起提交」之后。练习从[已有配套](https://github.com/SamChowRock/epp-public/tree/part-06/chapter-49)的副本开始。

## 50.1 为两个已在使用的分支各留一份基线

学过小程序登录的读者保留旧练习库，记录应用范围内的平台身份映射、本地账号、旧素材、有效 mini Bearer 和 Web Cookie。另一条路线从事务发件箱章取得非空副本，记下密码账号、旧意图、已提交待发消息及其 ID。先分别读各自的迁移历史。只做主线的读者可直接继续，选读者需等发件箱章完成再回来。

## 50.2 让两种迁移历史都能走到同一结构

从共同祖先比对小程序会话及映射、发件箱结构、Nest 模块、身份中间件和环境配置，保留两边已执行的迁移文件及摘要。在两份独立副本上各应用自己缺失的迁移，再与从空库完整引导的结构逐项核对。遇到重复对象、迁移相互依赖或漂移时停在副本中定位，勿把删库或清空迁移记录当成已验证的升级。

## 50.3 用 Cookie 与 Bearer 找回同一条旧素材

在小程序历史副本以原两份凭据分别读同一素材，检查同一 userId、素材 ID、修订号；切到乙的 mini Bearer 后读取甲的素材应得 404。关闭 mini 资格，分别核查它对 Web Cookie 与 mini 会话的影响。旧发件箱副本按原 ID 查回旧消息与意图，再经真实 HTTP 请求新验证并从练习接收端核对新投递，防止合并时退回同步发送。

## 50.4 让选读入口可以退出

分别测试小程序未配置时保留 Web 登录与发件箱、SMTP 不可用时保留旧素材读取。演练关闭小程序入口后处理已签发 Bearer 的规则，并以两份独立副本重复启动、读取和消息核对，写出下一章应选的代码与数据库。
