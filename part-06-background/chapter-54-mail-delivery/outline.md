# 第 54 章 选读：追踪一封事务邮件的实际送达与异步退信

**选读章**　接在第 53 章「失败、重试与未知结果」之后。练习从[已有配套](https://github.com/SamChowRock/epp-public/tree/part-06/chapter-53)的副本开始。

## 54.1 从本地接收跨到受控邮箱

沿用验证意图、Outbox、投递尝试和通道停发记录。准备已获准发送的测试域、供应商发信身份与自己控制的收件箱，按提供方要求验证域名、发件身份与回执入口。开发环境仍可用本地 SMTP。练习中用请求 ID、消息 ID、尝试 ID 和供应商接受的标识建立对应，令牌与邮箱凭据不进样例。

## 54.2 把接收应答与收件箱证据配成一组

向受控地址发起一次新验证，记录 API 应答、Worker 最终应答、提供方接受时间和邮件原始头中的关联信息。由收件端找到本次邮件，实际打开一次验证链接并确认消费结果。按另一地址安排提供方支持的异步退信测试，先看已接受，稍后再查回执；供应商模拟地址单列为模拟，不计入真实邮箱送达。

## 54.3 把重复、迟到和伪造回执送入入口

计划接入提供方签名事件，用原始正文验签，并按事件身份去重，把退信作为追加事实关联原尝试。对同一事件发送两次，再重播早先的接受通知及一份错误签名。对照历史应看到一次有效退信、接受事实仍在，不能关联的事件进入待核对记录。明确短暂延迟和永久退信对后续发送的不同影响。

## 54.4 恢复一个地址并保留事故线索

模拟地址写错和全通道未知两种事故，按地址处置退信，核对另一地址仍能投递；回到现有停发流程处理通道未知。更新收件地址后发起新的验证，旧回执仍指向原尝试。隔离交付路线列为选读，交付要求含真实邮箱时纳入验收。本章为规划，真实供应商、收件箱、验签与异步退信都待现场实测。
