# 第六篇　请求返回以后：后台任务与用户通知

注册页告诉用户去查邮件时，数据库里可能已有一份十五分钟后到期的验证意图，收件箱却是空的。上一章把 API 停在这两件事之间。现在关掉那台 API，换一个进程：它凭什么知道还有哪封信要寄？如果它发现信已经寄过一半，又凭什么决定再寄一次？

本篇从[第五篇回顾的故障现场](../part-05-identity/chapter-41-review/chapter.md#415-邮件请求返回以后谁接着做)继续，代码接第 36 章的密码路线。带着该章的独立验证库、注册／重置请求和本机 Mailpit 即可开始。可选平台登录的账号和迁移留在各自的练习库。

注册或重置**申请**获准签发时，事务同时留下验证意图和待寄的邮件。冷却期间重复申请也会返回 202，可以按本轮消息 ID 核对是否真的增加了工作。第 42～45 章跟着同一封信走：从事务中留下投递工作，交给独立进程，再判断谁有权发送、失败后是否还能重试。SMTP 接受邮件以后，用户仍要带着证明回来确认。

到第 46 章，产生后台工作的时刻变了。注册或重置**确认成功**，账号已经创建或密码已经改变，接下来要把这次结果记入该账号的站内收件箱。第 47 章再让开着的页面及时发现变化。页面断线时，用户回来仍能按当前身份查询。第 48 章从值班交接开始：用户已经改了密码，收件箱还停在旧页面，同事却要放行邮件通道。先选择证据并给出处置意见，再复现这两个现场。
