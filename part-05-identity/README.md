# 第五篇 让服务认识用户：身份、会话与权限

前四篇已经建立记录、修订、候选、采纳与学习查询，并让竞争和重试有确定的结果。现在这些操作还使用同一个固定开发用户。本篇从保护凭据开始，逐步让服务验证调用者、管理登录状态，再判断他能否操作某份资源。

第37章保留原用户和所有记录，只增加密码凭据与本地初始化。第38章从真实请求识别用户、管理会话并处理改密竞争；第39章接上账号状态与当前入口资格；第40章建立浏览器入口保护，第41章让两个实例用数据库原子决定共享登录额度。第42章先验证邮箱并建立账号，第43章再用原账号重置密码、撤销旧会话；第44～47章是可选登录分支。核心路线完成第43章后可进入第48章回顾；外部平台的真实接入按各章条件另行准备，不阻塞密码登录主线。

第 44 章复用已有用户、会话与权限，只准备登录所需的最小小程序入口。第 45 章先解释 OAuth／OIDC 协议，再接外部身份；其中第 45.1～45.3 节也是后续 MCP 授权的前置知识，可以单独补读，无需先完成 OIDC 平台接入。第 46 章承接这部分协议基础并沿用第 44 章的微信身份映射；第 47 章需要第 44 章的小程序会话和已有网站会话。第 48 章在完成第 37～43 章后回顾核心路线，可选登录入口只核对自己已经选择的部分。
