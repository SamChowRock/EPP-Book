# 第五篇 让服务认识用户：身份、会话与权限

前四篇已经建立记录、修订、候选、采纳与学习查询，并让竞争和重试有确定的结果。现在这些操作还使用同一个固定开发用户。本篇从保护凭据开始，逐步让服务验证调用者、管理登录状态，再判断他能否操作某份资源。

第37章保留原用户和所有记录，只增加密码凭据与本地初始化。第38章从真实请求识别用户、管理会话并处理改密竞争；第39章接上账号状态与当前入口资格；第40章建立浏览器入口保护，第41章讨论两个实例怎样共享登录额度。第42章先验证邮箱并建立账号，第43章再用原账号重置密码、撤销旧会话；第44～47章是可选登录分支。核心路线完成第43章后可进入第48章回顾；外部平台的真实接入按各章条件另行准备，不阻塞密码登录主线。

本篇已有七条知识支线，承担主线方案之外的机制与设计推导；它们与第44～47章可按需接入的平台登录分支用途不同。

- [38A：Session、JWT与撤销时效，怎样从需求选方案](chapter-38-sessions/side-01-session-decisions.md)：以设备丢失和时限变化推导状态、缓存与验签的取舍，阅读约35～45分钟。
- [39A：从“我的记录”走到团队权限](chapter-39-authorization/side-01-authorization-models.md)：以双资料库推导角色、关系、动作、查询范围和撤销竞争，阅读约40～50分钟。

- [43A：换邮箱、短验证码与恢复渠道，怎样避免把账号交错人](chapter-43-registration/side-01-recovery-identity.md)：以渠道变化推导联系版本、短码预算与恢复权限，阅读约30～40分钟。

- [44A：同一个人、两份账号——跨应用身份与账号合并](chapter-44-mini-program/side-01-account-linking.md)：改变应用范围、绑定冲突与恢复条件，推导关联、合并与解绑，阅读约25～35分钟。

- [46A：扫了转发来的二维码，会登录哪台电脑](chapter-46-wechat-website/side-01-qr-consent.md)：比较转发回调、替换未用授权码与转发二维码，区分身份、设备和具体操作确认，阅读约12～17分钟，本地复现另加5～10分钟。

- [47A：从两秒轮询到一万个等待中的页面](chapter-47-mini-confirm/side-01-polling.md)：按等待人数、连接开销和断线时点比较轮询与推送，阅读约10～15分钟。
