# 第五篇 让服务认识用户：身份、会话与权限

前四篇已经建立记录、修订、候选、采纳与学习查询，并让竞争和重试有确定的结果。现在这些操作还使用同一个固定开发用户。本篇从保护凭据开始，逐步让服务验证调用者、管理登录状态，再判断他能否操作某份资源。

第32章保留原用户和所有记录，只增加密码凭据与本地初始化。第33～36章依次建立会话、权限、浏览器入口保护和注册恢复；第37～40章是可选登录分支。核心路线完成第36章后可进入第41章回顾；外部平台的真实接入按各章条件另行准备，不阻塞密码登录主线。

| 章节 | 本章推进 |
| --- | --- |
| [第32章 安全地保存密码与秘密](chapter-32-secrets/chapter.md) | 区分秘密的保护方式，量密码计算成本，为原用户增加凭据 |
| 第33章 Session 与 Cookie 登录状态从哪里来 | 使用已有凭据登录，管理会话并替换固定身份 |
| 第34章 鉴权与授权 登录了也不代表能操作 | 检查账号状态、权限与资源归属 |
| 第35章 保护基于浏览器的服务入口 | 建立跨域、CSRF、请求和计算成本边界 |
| 第36章 注册 验证与密码重置 | 接通注册与恢复，先同步发送本地邮件 |
| 第37章 小程序登录与独立会话 | 可选：平台身份映射到本地用户 |
| 第38章 先理解 OAuth，再接入 OIDC 外部登录 | 可选：先理解协议角色，再接外部身份 |
| 第39章 微信网站扫码登录 | 可选：网站扫码与平台身份映射 |
| 第40章 用已登录的小程序扫码确认网站登录 | 可选：登录票据、用户确认与一次性消费 |
| 第41章 第五篇回顾：身份有效之后，操作是否仍被允许 | 综合身份、状态与权限判断 |

第32章阅读约100～120分钟，编码与跟做另加65～90分钟，按实际成稿估算；其余章节完成后再计时，不预估全篇总量。

本篇从已有数据库继续，切换代码不能代替迁移。DEV、VERIFY与测试连接分别核对；新增凭据不会自动保护旧接口，第33～35章会逐步接好请求入口。本章结束后可以保留数据暂停，下次先确认迁移与凭据状态，从验证密码继续，不覆盖初始化。
