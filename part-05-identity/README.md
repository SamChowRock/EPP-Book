# 第五篇 让服务认识用户：身份、会话与权限

前四篇已经建立记录、修订、候选、采纳与学习查询，并让竞争和重试有确定的结果。现在这些操作还使用同一个固定开发用户。本篇从保护凭据开始，逐步让服务验证调用者、管理登录状态，再判断他能否操作某份资源。

第32章保留原用户和所有记录，只增加密码凭据与本地初始化。第33章从真实请求识别用户、管理会话并处理改密竞争；第34章接上账号状态与当前入口资格；第35章建立浏览器入口保护，第36章继续注册恢复；第37～40章是可选登录分支。核心路线完成第36章后可进入第41章回顾；外部平台的真实接入按各章条件另行准备，不阻塞密码登录主线。

| 章节 | 本章推进 |
| --- | --- |
| [第32章 安全地保存密码与秘密](chapter-32-secrets/chapter.md) | 区分秘密的保护方式，量密码计算成本，为原用户增加凭据 |
| [第33章 Session 与 Cookie 登录状态从哪里来](chapter-33-sessions/chapter.md) | 使用已有凭据登录，管理会话并替换固定身份 |
| [第34章 鉴权与授权 登录了也不代表能操作](chapter-34-authorization/chapter.md) | 用第二账号核对归属，观察默认拒绝、旧会话恢复与权限竞争 |
| [第35章 保护基于浏览器的服务入口](chapter-35-browser-boundary/chapter.md) | 用真实浏览器区分CSRF拒绝、预检与响应读取，并界定代理与成本 |
| [第36章 注册、验证与密码重置](chapter-36-registration/chapter.md) | 注册和一次消费、凭据版本与会话撤销、本地SMTP闭环 |

| [第39章 微信网站扫码登录](chapter-39-wechat-website/chapter.md) | 可选：一次性领取浏览器登录事务，关联原账号并核对 Web 资格 |

| [第41章 第五篇回顾：身份有效之后，操作是否仍被允许](chapter-41-review/chapter.md) | 用同一素材定位 401、403 和 404，核对重置前后的证明与邮件投递缺口 |

第32章阅读约100～120分钟，编码与跟做另加65～90分钟，按实际成稿估算；第33章阅读约130～155分钟，编码与跟做另加155～195分钟；第34章阅读约85～105分钟，编码与跟做另加90～120分钟；第35章阅读约120～145分钟，编码与跟做另加110～145分钟；第36章阅读约155～185分钟，编码、迁移、邮件联调与产物核对另加165～210分钟；第37章阅读约130～160分钟，本地编码与跟做另加145～190分钟，具备平台条件后真实联调另加45～70分钟；第38章阅读约75～100分钟，本地实现、迁移与联调另加100～140分钟；第39章阅读约35～50分钟，实现与本地联调另加70～100分钟，平台申请和部署另计；第40章阅读约45～60分钟，编码、迁移与本地联调另加90～125分钟，真机接入另计；第41章阅读约42～55分钟，双账号联调、邮件恢复与故障观察另加65～85分钟。

第五篇按成稿与实际操作步骤估算。核心路线（第 32～36、41 章）阅读约 632～765 分钟，跟做另加 650～845 分钟。四个可选登录分支全部跟做时，额外阅读约 285～370 分钟，本地操作另加 405～555 分钟。七条知识支线全部阅读另加 167～224 分钟，39A 的本地复现另加 5～10 分钟。真实平台申请、部署与真机联调另计。

本篇已有七条知识支线，承担主线方案之外的机制与设计推导；它们与第37～40章可按需接入的平台登录分支用途不同。

- [33A：Session、JWT与撤销时效，怎样从需求选方案](chapter-33-sessions/side-01-session-decisions.md)：以设备丢失和时限变化推导状态、缓存与验签的取舍，阅读约35～45分钟。
- [34A：从“我的记录”走到团队权限](chapter-34-authorization/side-01-authorization-models.md)：以双资料库推导角色、关系、动作、查询范围和撤销竞争，阅读约40～50分钟。

- [36A：换邮箱、短验证码与恢复渠道，怎样避免把账号交错人](chapter-36-registration/side-01-recovery-identity.md)：以渠道变化推导联系版本、短码预算与恢复权限，阅读约30～40分钟。

- [37A：同一个人、两份账号——跨应用身份与账号合并](chapter-37-mini-program/side-01-account-linking.md)：改变应用范围、绑定冲突与恢复条件，推导关联、合并与解绑，阅读约25～35分钟。
- [38A：登录事务遇到多实例和密钥轮换](chapter-38-oidc/side-01-trust-and-transactions.md)：从条件消费与签名信任判断重启、轮换和撤权，阅读约15～22分钟。

- [39A：扫了转发来的二维码，会登录哪台电脑](chapter-39-wechat-website/side-01-qr-consent.md)：比较转发回调、替换未用授权码与转发二维码，区分身份、设备和具体操作确认，阅读约12～17分钟，本地复现另加5～10分钟。

- [40A：从两秒轮询到一万个等待中的页面](chapter-40-mini-confirm/side-01-polling.md)：按等待人数、连接开销和断线时点比较轮询与推送，阅读约10～15分钟。

支线时间单列，不计入主线估时。

本篇从已有数据库继续，切换代码不能代替迁移。DEV、VERIFY与测试连接分别核对；新增凭据不会自动保护旧接口，第33～35章会逐步接好请求入口。第32章后从验证密码恢复，不覆盖初始化；第33章后先确认会话迁移与目标库，再登录恢复，不重新导入旧记录。
