# 第五篇 让服务认识用户：身份、会话与权限

前四篇已经建立记录、修订、候选、采纳与学习查询，并让竞争和重试有确定的结果。现在这些操作还使用同一个固定开发用户。本篇从保护凭据开始，逐步让服务验证调用者、管理登录状态，再判断他能否操作某份资源。

第32章保留原用户和所有记录，只增加密码凭据与本地初始化。第33章从真实请求识别用户、管理会话并处理改密竞争；第34章接上账号状态与当前入口资格；第35章建立浏览器入口保护，第36章继续注册恢复；第37～40章是可选登录分支。核心路线完成第36章后可进入第41章回顾；外部平台的真实接入按各章条件另行准备，不阻塞密码登录主线。

| 章节 | 本章推进 |
| --- | --- |
| [第32章 安全地保存密码与秘密](chapter-32-secrets/chapter.md) | 区分秘密的保护方式，量密码计算成本，为原用户增加凭据 |
| [第33章 Session 与 Cookie 登录状态从哪里来](chapter-33-sessions/chapter.md) | 使用已有凭据登录，管理会话并替换固定身份 |
| [第34章 鉴权与授权 登录了也不代表能操作](chapter-34-authorization/chapter.md) | 用第二账号核对归属，观察默认拒绝、旧会话恢复与权限竞争 |
| [第35章 保护基于浏览器的服务入口](chapter-35-browser-boundary/chapter.md) | 用真实浏览器区分CSRF拒绝、预检与响应读取，并界定代理与成本 |
| [第36章 注册、验证与密码重置](chapter-36-registration/chapter.md) | 注册和一次消费、凭据版本与会话撤销、本地SMTP闭环 |
| 第37章 小程序登录与独立会话 | 可选：平台身份映射到本地用户 |
| 第38章 先理解 OAuth，再接入 OIDC 外部登录 | 可选：先理解协议角色，再接外部身份 |
| 第39章 微信网站扫码登录 | 可选：网站扫码与平台身份映射 |
| 第40章 用已登录的小程序扫码确认网站登录 | 可选：登录票据、用户确认与一次性消费 |
| 第41章 第五篇回顾：身份有效之后，操作是否仍被允许 | 综合身份、状态与权限判断 |

第32章阅读约100～120分钟，编码与跟做另加65～90分钟，按实际成稿估算；第33章阅读约125～150分钟，编码与跟做另加150～190分钟；第34章阅读约85～105分钟，编码与跟做另加90～120分钟；第35章阅读约120～145分钟，编码与跟做另加110～145分钟；第36章阅读约150～180分钟，编码、迁移、邮件联调与产物核对另加160～205分钟；其余章节完成后再计时，不预估全篇总量。

本篇已有三条知识支线，承担主线方案之外的机制与设计推导；它们与第37～40章可按需接入的平台登录分支用途不同。

- [33A：Session、JWT与撤销时效，怎样从需求选方案](chapter-33-sessions/side-01-session-decisions.md)：以设备丢失和时限变化推导状态、缓存与验签的取舍，阅读约35～45分钟。
- [34A：从“我的记录”走到团队权限](chapter-34-authorization/side-01-authorization-models.md)：以双资料库推导角色、关系、动作、查询范围和撤销竞争，阅读约40～50分钟。

- [36A：换邮箱、短验证码与恢复渠道，怎样避免把账号交错人](chapter-36-registration/side-01-recovery-identity.md)：以渠道变化推导联系版本、短码预算与恢复权限，阅读约30～40分钟。

支线时间单列，不计入上述主线估时；三条合计阅读约105～135分钟，复用已有会话、权限及恢复模型，没有新增运行步骤。

本篇从已有数据库继续，切换代码不能代替迁移。DEV、VERIFY与测试连接分别核对；新增凭据不会自动保护旧接口，第33～35章会逐步接好请求入口。第32章后从验证密码恢复，不覆盖初始化；第33章后先确认会话迁移与目标库，再登录恢复，不重新导入旧记录。
