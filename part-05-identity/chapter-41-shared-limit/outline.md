# 第 41 章 两个 API 实例如何共用登录额度

**章节提要**　承接第 40 章「保护基于浏览器的服务入口」。练习从[已有配套](https://github.com/SamChowRock/epp-public/tree/part-05/chapter-40)的副本开始。

## 41.1 交替访问两个独立端口

沿用浏览器入口已有的每来源每分钟十次密码请求，在同一台主机以相同回环地址访问两个 API。用格式合法的错误凭据交替请求，保留端口、序号、状态与错误码。单进程 Map 都在工作时，第十一次仍可能到达密码验证；停掉一个实例再启动，检查它记得哪些请求。

## 41.2 在数据库内作出一次配额决定

复用已有 PostgreSQL，设计按可信来源及规则标识的计数行，用数据库时间判定本窗口是否到期，在同一原子操作内建行、重开窗口或消耗一格。明确首次计时及十次包含失败请求；使用有界过期清理和新来源容量策略。每实例密码并发占位仍按该进程资源核算。匿名来源不得通过任填转发头换桶。

## 41.3 在只余一格时同时发起

先让两个端口共用九次，再用两个客户端同时发送。预期恰一条进入凭据判断，一条返回 AUTH_RATE_LIMIT 及 Retry-After。等到窗口实际结束验证可再试；重启实例、变换伪造头、并行首次建桶都需复查。用另一个已登录会话继续普通读取，避免误把登录拒绝解释为会话撤销。

## 41.4 当共享计数不可用时怎样恢复

定向撤去实验角色对计数表的访问，检查密码入口能否返回依赖不可用，并保留请求编号；复原权限后观察已有窗口继续生效。与所有 API 均断库分别判断。交付时记录两个端口及同一共享库身份，容器部署照用相同协议。
