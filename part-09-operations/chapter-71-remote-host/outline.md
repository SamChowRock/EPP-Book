# 第 71 章 用 iTerm2 经 SSH 接手另一台主机上的服务

**章节提要**　承接第 70 章「在本机直接部署服务」。练习从[已有配套](https://github.com/SamChowRock/epp-public/tree/part-09/chapter-70)的副本开始。

## 71.1 先识别将要接手的主机

从已有原生部署交接单取得目标地址、SSH 端口、运维账号和由控制台或管理员提供的主机公钥指纹。iTerm2 中保留本地标签页，另开远端标签页连接，比对首次连接指纹。运行 hostname、id、pwd 和 uname，记录哪台机器在解释命令，再辨认它的托管器、运行目录、当前发布及目标库。

## 71.2 通过隧道核对只监听回环的 API

选择空闲本地端口，从本机执行 ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:13358:127.0.0.1:3358 练习主机别名。分别在远端测 3358，在本机测 13358；核对匿名请求、日志中的请求 ID 与旧收据。远端端口应换成本次部署实际值。如果连接失败，先看 SSH 是否连上，再查本机转发端口是否已被占用，最后从远端主机访问 API 的监听端口。

## 71.3 断开终端以后由谁维持服务

远端查看服务 PID 和最近就绪时间，关闭隧道再退出交互 SSH；从第二连接确认托管进程仍在，重新转发后同一服务可读。再对照一次在交互终端启动的练习命令，说明 PTY 和托管器各自负责什么。日志与文件交换用专属目录，比对传输前后摘要，不需要把数据库和存储的监听开到公网。

## 71.4 在主机身份改变时恢复接手

在一次性目标上安排已知的主机密钥更换，保留 SSH 拒绝的主机名与端口。通过独立管理渠道重新核对新指纹后，只更新对应条目，再检查来自新连接的运行身份、旧收据和进程日志。要求交接两端读数、端口映射和断开重连证据。
