# 第 75 章 客户端怎样确认访问的是自己的 HTTPS 服务

**教学规划**　接在第 74 章「运行环境变了，怎样交付同一份服务」之后。

## 75.1 先让客户端按名字找到目标

沿用跨环境部署的回环 API 与第二台练习主机，约定练习域名和终结 TLS 的入口。用客户端的名称解析或 curl --resolve 将该名字指到练习地址，记录普通 HTTPS 请求连接到哪里。请求使用域名以保留 SNI 和主机名校验。先核对 TCP 能否建立，避免把端口拒绝当作证书错误。

## 75.2 签一张带正确名称的练习证书

准备独立练习 CA 与叶证书，将服务名放进 subjectAltName，配置入口提供叶证书及所需中间证书，仅部署叶私钥。客户端先不信任该 CA，再用 curl --cacert 指向练习根证书。记录两次验证结果、证书名称、有效期与业务状态；成功握手后 API 仍可因缺会话返回 401。

## 75.3 用两个客户端复现名称和信任差异

通过同一地址访问一个不在证书内的名字，观察即使根已信任，名称检查仍会失败。让浏览器使用单独测试配置，核对它信任的根与命令行所用 CA；再检查上游 API 的监听与公开 Origin，避免把混合内容、Cookie 或 CSRF 的拒绝记成 TLS 握手错误。全过程不用跳过证书校验。

## 75.4 换证后回到原业务请求

准备同名新叶证书、受限私钥和可回退的入口配置，重载后开新连接读取序列号与有效期，再用旧会话复读原素材。删除临时信任和测试解析，恢复入口。核心原生及可选容器路线共用这组验收，公网 DNS、公共 CA 签发和反代转发仍由后续相应章节展开。
