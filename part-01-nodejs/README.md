# 第一篇 先运行起来：从浏览器走进 Node.js

我们先写一个能保存英语原文的小服务。用户可以记下一句话，再按记录编号找回来。等到想保存修改前的写法、区分谁能看到哪条记录、让别人也能访问时，我们再沿着同一个项目处理数据库、权限和部署。

项目一直用下去，同一段代码会遇到新的要求。比如，接入数据库后，接口要读回此前保存的数据；增加修订后，旧记录要能够进入新的结构；拆出后台任务后，中断的工作要有明确的恢复依据。随着项目演进，我们会逐步建立独立实现和维护后端所需的能力。

第一篇先把运行基础建立起来。我们将用 Node.js 的 HTTP 模块编写一个小服务，直接处理请求和响应，并为它建立调试、启动和构建方式。选择这个起点，是为了能沿着自己写的代码观察请求如何被处理、程序如何保持运行，以及错误怎样影响进程。第二篇迁入 Nest 时，再看框架如何组织这些已经接触过的职责。

服务的功能先限定为英语原文的新增、列表和详情，数据暂存在内存中。在这个范围内，请求处理代码足够少，可以集中观察工作目录、环境变量、事件循环和模块加载等运行问题。我们也会比较开发时直接运行 TypeScript 与运行编译产物的差别，为后续扩展服务准备稳定的开发入口。

动手之前，第 0 章先跟踪一句英语从写下到收录的过程，看看用户如何修改原文、审阅和采纳建议，这些操作会带来哪些数据与执行上的要求。第 1 章从文件和日志学会操作 Shell，再把同一个检查交给多份输入，在另一个终端观察它的配置与进程。第二章先完成第一次 HTTP 往返，第三章接着实现受限的正文读取与保存；第四至六章继续使用这份代码，深入理解 Node.js 的运行机制；第七章回顾能力边界，并通过独立需求变更与改变后的运行条件综合应用。

**阅读路径**：核心实践，按第 0～7 章顺序阅读。

**起点**：已有 JavaScript、前端开发和前后端联调经验；熟悉 `async/await`、模块导入和接口调用，需要系统掌握后端的实现技术。实践项目从空目录开始。

**本篇结果**：能在本机启动、调用、调试和停止一个内存版记录服务，解释浏览器与 Node.js 的运行差异，建立 TypeScript 的开发与构建命令，并能独立实现有兼容约束的小需求、验证交付产物。

Node.js 的资源生命周期会在第 14、51、63 章继续展开，流与背压在第 59～60 章展开，性能诊断在第 65 章展开，长期运行与进程托管在第 70 章展开，模块与交付在第 64、78、102 章继续应用。各阶段共同建立独立使用 Node 开发和维护后端所需的能力，完整对应关系见[目标与能力路线](../backend-capabilities.md)。

**阶段边界**：单包、单个服务进程、内存记录。主线最小记录只有 ID、英语原文和创建时间；第七章来源标签只在隔离实验中实现，不进入后续主线；Nest 在第二篇接入，PostgreSQL 与中文意图在第三篇加入。修订、候选、采纳、身份和后台任务在后续篇章逐步实现。第 0 章解释这些需求为何出现，第二章开始创建程序并准备运行环境。Docker 不是前置条件。

可以分三段完成本篇，每次停下来都留下一份下次能复查的结果。

- **第 0～3 章**选一句自己编写的英文。先说清系统应保存谁提供的原文，再用 Postman 创建记录并另发请求按 ID 读取。再次主动提交同一句，预测列表里有几条、两个详情编号是否相同。保留请求，记录重启前后的结果。
- **第 4～5 章**故意只改一个运行条件。换工作目录时，先预测程序会去哪儿找配置；让一个请求等待时，给同一进程发另一个普通读取。把预测、观测与恢复后的结果记在一起，下一次遇到“服务没反应”才知道哪一种解释值得先查。
- **第 6～7 章**把产物搬离源码目录，用同一组请求验收，然后在隔离练习中加入来源标签。旧请求、新请求和被拒绝的请求各查一次；若只验证新页面能用，无法说明已有调用方还能接着用。第 7 章完成后，第 8 章从主服务接续。

### 第 1 章知识支线

- [支线 1A　交付目录里，两个名字指向的是哪一份文件](chapter-01-unix-shell/side-01-file-identity.md)。两个名字都能读到旧稿，改了一份另一个会不会跟着变？用同一份说明核对权限、链接、搬移与回滚。
- [支线 1B　一份文本报表怎样做到不重算、不漏算](chapter-01-unix-shell/side-02-text-reports.md)。从早晚班的九行记录找出六个请求，再用 awk 合并修订、补上零请求的区域，验证重放不多算。
- [支线 1C　终端里成功的任务，换成定时运行为什么会失败](chapter-01-unix-shell/side-03-unattended-job.md)。逐次拿走工作目录、窗口变量和键盘输入，观察超时、中断与重叠运行以后还能交出哪一份报告。
- [支线 1D　在自己的电脑上打开了页面，交给别人还能打开吗](chapter-01-unix-shell/side-04-portable-archive.md)。把能打开的页面制成归档，在新旧收件目录打开同一包，分辨标题、资源、版本和传输完整性。

### 第 4 章知识支线

第四章的运行判断继续在下面三条支线中展开，结合机制、代码和改变条件后的结果，建立对通道、文件与退出过程的独立判断。

- [支线 4A：输出去了哪里——文件描述符、重定向与管道](chapter-04-node-runtime/side-01-stdio-and-pipes.md)：观察输出与诊断的去向，并用两次导出比较何时可以替换正式文件。阅读约 12～15 分钟，操作另加约 9～12 分钟。
- [支线 4B：文件明明在那里，为什么读不到——路径、权限与句柄](chapter-04-node-runtime/side-02-files-permissions-handles.md)：推导目录与文件权限，处理打开资源的成功和异常路径。阅读约 18～22 分钟，操作另加约 6～10 分钟。
- [支线 4C：收到停止信号之后，程序为什么还活着](chapter-04-node-runtime/side-03-process-lifetime-signals.md)：从定时任务推导停止入口、等待已有工作与资源释放。阅读约 14～18 分钟，操作另加约 5～8 分钟。


### 第 5 章知识支线

第五章的两条支线分别补足调度判断与线程生命周期，配套示例均可在不启动 HTTP 服务的情况下运行。

- [支线 5A：await 之后轮到谁——微任务、nextTick 与事件循环阶段](chapter-05-event-loop/side-01-scheduling-and-microtasks.md)：移动入队的位置，对照 ESM 顶层、I/O 回调与有限微任务链的调度顺序。阅读约 14～17 分钟，操作另加约 7～10 分钟。
- [支线 5B：把计算交给另一个线程——消息、失败与 Worker 的寿命](chapter-05-event-loop/side-02-worker-lifecycle.md)：观察消息复制、缓冲区转移后的所有权，以及正常结果、异常和无结果退出。阅读约 20～25 分钟，操作另加约 10～15 分钟。
