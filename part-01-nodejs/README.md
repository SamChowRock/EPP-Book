# 第一篇 先运行起来：从浏览器走进 Node.js

接下来的实践，会把一个最小的 Node.js 服务逐步建设成能够保存数据、处理并发、执行后台任务，并且可以部署和维护的公开 EPP。我们会一直沿用同一个项目：先让接口运行起来，再组织代码、接入数据库，随后处理业务规则、身份与权限，最终将这些能力用于表达管理、AI 和练习。

这条路线也决定了技术的讲解方式。每引入一个机制，都要把它接回已有代码，观察它带来了什么变化。例如，接入数据库后，接口要读回此前保存的数据；增加修订后，旧记录要能够进入新的结构；拆出后台任务后，中断的工作要有明确的恢复依据。随着项目演进，我们会逐步建立独立实现和维护后端所需的能力。

第一篇先把运行基础建立起来。我们将用 Node.js 的 HTTP 模块编写一个小服务，直接处理请求和响应，并为它建立调试、启动和构建方式。选择这个起点，是为了能沿着自己写的代码观察请求如何被处理、程序如何保持运行，以及错误怎样影响进程。第二篇迁入 Nest 时，再看框架如何组织这些已经接触过的职责。

服务的功能先限定为英语原文的新增、列表和详情，数据暂存在内存中。在这个范围内，请求处理代码足够少，可以集中观察工作目录、环境变量、事件循环和模块加载等运行问题。我们也会比较开发时直接运行 TypeScript 与运行编译产物的差别，为后续扩展服务准备稳定的开发入口。

动手之前，第一章先交代这个记录服务在 EPP 中的位置：它接收的内容以后如何被修订、整理和采纳，这些操作会带来哪些数据与执行上的要求。有了这个背景，第二章便开始编写最小实现；第三至五章继续使用这份代码，深入理解 Node.js 的运行机制；第六章回顾能力边界，并在改变后的运行条件下综合应用。

**阅读路径**：核心实践，按第 1～6 章顺序阅读。

**起点**：已有 JavaScript、前端开发和前后端联调经验；熟悉 `async/await`、模块导入和接口调用，需要系统掌握后端的实现技术。实践项目从空目录开始。

**本篇结果**：能在本机启动、调用、调试和停止一个内存版记录服务，解释浏览器与 Node.js 的运行差异，并建立 TypeScript 的开发与构建命令。

这些是本篇要建立的具体能力。Node.js 的资源生命周期会在第 13、43、53 章继续展开，流与背压在第 50～51 章展开，性能与长期运行在第 55～57 章展开，模块与交付在第 54、65、88 章继续应用。各阶段共同建立独立使用 Node 开发和维护后端所需的能力，完整对应关系见[目标与能力路线](../backend-capabilities.md)。

**阶段边界**：单包、单个服务进程、内存记录。最小记录只有 ID、英语原文和创建时间；Nest 在第二篇接入，PostgreSQL 与中文意图在第三篇加入。修订、候选、采纳、身份和后台任务在后续篇章逐步实现。第一章解释这些需求为何出现，第二章开始创建程序并准备运行环境。Docker 不是前置条件。
